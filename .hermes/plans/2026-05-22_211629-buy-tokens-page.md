# Buy Tokens Page Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a visible customer-facing Buy Tokens page/flow to WOLF-FD so users can buy BotBot/AI token packs through Shopify and redeem pending claim codes inside the dashboard.

**Architecture:** Keep Shopify checkout as the payment provider, not custom card handling. The frontend will show token-pack cards and send users to Shopify product/checkout links; the backend webhook already credits paid orders into `botbot_token_ledger.tokens_purchased` when the Shopify customer email matches a dashboard user. Add a lightweight claim-code UI for orders that cannot be auto-matched.

**Tech Stack:** React + TypeScript + Tailwind in WOLF-FD frontend, existing `services/botbotApi.ts` fetch pattern, Express backend route already started at `POST /api/shopify/topup/claim`, Shopify paid-order webhook at `POST /api/shopify/topup/webhook`.

## Assumptions

- The first visible page should live inside the existing dashboard, not a separate public marketing site.
- Best first placement: add an `AI Tokens` / `Buy Tokens` sub-tab inside the existing Shop module, then link to it from BotBot’s quota/usage area.
- Shopify product/checkout links are public URLs and safe to store in frontend config once created.
- Secrets stay backend-only:
  - Do not expose `SHOPIFY_TOPUP_WEBHOOK_SECRET` in frontend code.
  - Do not expose Admin API tokens.
- The frontend can ship with placeholder disabled pack cards if final Shopify product URLs are not ready, but the better finish is to wire real Shopify product links.

## Proposed User Flow

1. User opens dashboard.
2. User clicks `Shop`.
3. User selects new `AI Tokens` sub-tab.
4. Page shows:
   - current token usage / remaining tokens
   - token-pack cards
   - `Buy with Shopify` buttons
   - claim-code redemption form
   - note explaining that matching Shopify checkout email auto-credits tokens
5. If user clicks a pack, open Shopify checkout/product in a new tab.
6. Shopify paid-order webhook credits tokens automatically when email matches a dashboard user.
7. If auto-match fails, the user can enter a claim code in the dashboard and POST to `/api/shopify/topup/claim`.

## Risks / Tradeoffs

- **No Shopify products yet:** page can render but Buy buttons must be disabled or use placeholder links until product URLs exist.
- **Admin API token still unresolved:** not required for manual webhook setup, but needed if we want the agent to create products/webhooks automatically via Shopify Admin API.
- **Email matching is brittle:** auto-credit depends on Shopify checkout email matching dashboard login email. Claim-code fallback covers this.
- **Webhook secret handling:** frontend must never see webhook secrets. Only backend env.
- **Current repo has unrelated dirty files:** implementation/deploy must preserve unrelated changes and commit only intended files.
- **Full backend test may fail locally without Postgres:** classify that as environment/setup failure unless product routes are reached and failing.
